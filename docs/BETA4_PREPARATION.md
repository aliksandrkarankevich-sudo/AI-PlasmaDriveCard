# Подготовка 0.96.0-beta4

Эта инструкция описывает подготовку и проверку следующей beta-версии. Ветка `dev/v0.96-beta4` является рабочей: её существование **не означает публикацию релиза**.

## Правила цикла

До завершения проверки запрещено:

- создавать тег `v0.96.0-beta4`;
- запускать workflow Release для beta4;
- публиковать GitHub Release;
- объявлять beta4 доступной пользователям;
- заменять в README ссылку на опубликованную beta3.

Сначала изменяем интерфейс и документацию, затем собираем тестовый пакет локально, проверяем его и только после исправления замечаний принимаем отдельное решение о pre-release.

## Рабочая ветка

```bash
cd ~/AI-PlasmaDriveCard
git fetch origin
git switch dev/v0.96-beta4
git pull --ff-only origin dev/v0.96-beta4
git status
```

Не вносите изменения beta4 непосредственно в `main`. Небольшие логически завершённые изменения коммитьте отдельно.

## Объём beta4

### Авторы и метаданные

- Проверить `package/metadata.json`.
- Убедиться, что имя проекта, описание, сайт, лицензия и список авторов корректны.
- Не повышать версию до `0.96.0-beta4` до завершения тестирования.
- Не переименовывать внутренний идентификатор виджета.

### Настройки

Главный файл: `package/contents/ui/ConfigGeneral.qml`.

Для каждого элемента настроек проверить:

1. Название точно объясняет, что изменится.
2. Русское и английское названия передают один смысл.
3. Термины одинаковы во всём окне и документации.
4. Указаны единицы измерения: проценты, пиксели, секунды или минуты.
5. Неочевидный параметр имеет краткое описание или подсказку.
6. Описание объясняет результат, а не повторяет название.
7. Опасные или необычные значения снабжены предупреждением.
8. Управление доступно с клавиатуры, а текст не обрезается при масштабировании.

Предлагаемая структура разделов:

- **Профили** — выбор, создание, сохранение, переименование и удаление наборов настроек.
- **Отображение** — автоматическая высота, масштаб текста, высота индикатора, отступы строк и максимальная высота.
- **Тома и значки** — корневой, загрузочный и системные разделы; общий стиль и индивидуальные значки.
- **Активность дисков** — индикация чтения/записи и интервал её обновления.
- **Фон и текст** — источник цвета, пользовательский цвет и прозрачность.
- **Форма карточки** — скругление, радиус, внутренний отступ и параметры перехода краёв.
- **Обновление и пороги** — период обновления, предупреждение и критический уровень заполнения.

Не менять существующие ключи `cfg_*` только ради улучшения текста. Это помогает сохранить настройки пользователей при обновлении с beta3.

## Стиль описаний

Хорошее название короткое: «Интервал обновления активности». Описание уточняет эффект: «Как часто проверять чтение и запись дисков. Меньшее значение быстрее реагирует, но чаще запускает проверку».

Для числовых параметров используйте единообразный формат:

- `Прозрачность фона, %`;
- `Радиус скругления, px`;
- `Интервал активности, с`;
- `Интервал обновления данных, с`;
- `Предупреждение о заполнении, %`;
- `Критическое заполнение, %`.

Не используйте внутренние термины QML в пользовательском интерфейсе. Например, вместо «edge opacity» объясняйте визуальный результат: «Непрозрачность края» или «Плавность перехода к прозрачности» — после проверки фактического поведения.

## Порядок работы

1. Составить таблицу всех текущих названий RU/EN и назначений параметров.
2. Проверить фактическое действие каждого параметра в виджете.
3. Согласовать новые названия и описания до изменения QML.
4. Внести правки без изменения ключей конфигурации.
5. Проверить окно на русском и английском языках.
6. Проверить масштабы Plasma 100%, 125%, 150% и 200%.
7. Собрать тестовый пакет, но не создавать тег и релиз.
8. Установить пакет как локальное обновление beta3.
9. Выполнить контрольный список ниже.
10. Исправить замечания и повторить проверку.
11. После одобрения обновить номер версии и подготовить отдельный PR к `main`.
12. Публиковать pre-release только отдельным действием после слияния и финальной проверки.

## Сборка без релиза

```bash
cd ~/AI-PlasmaDriveCard
git switch dev/v0.96-beta4
git pull --ff-only origin dev/v0.96-beta4
bash scripts/check.sh
bash scripts/build.sh
ls -lh dist/
```

Сборка локального файла в `dist/` не публикует релиз. Не выполняйте `git tag`, `git push --tags` и не запускайте Release workflow.

## Локальная установка

Сначала сохраните резервную копию конфигурации, если она существует:

```bash
mkdir -p ~/AI-PlasmaDriveCard-test-backup
cp ~/.config/plasma-org.kde.plasma.desktop-appletsrc ~/AI-PlasmaDriveCard-test-backup/ 2>/dev/null || true
```

Установите собранный пакет как обновление:

```bash
kpackagetool6 --type Plasma/Applet --upgrade dist/*.plasmoid
systemctl --user restart plasma-plasmashell.service
```

Если `--upgrade` сообщает, что пакет не установлен, используйте `--install`.

## Контроль настроек

- [ ] Все разделы и параметры понятны без чтения исходного кода.
- [ ] Каждая неочевидная настройка имеет описание.
- [ ] Единицы измерения указаны и одинаковы в RU/EN.
- [ ] Тексты полностью помещаются при масштабах 100–200%.
- [ ] Переключение RU/EN не требует сброса настроек.
- [ ] Изменение каждого параметра даёт ожидаемый визуальный результат.
- [ ] Значения по умолчанию соответствуют заводскому профилю.
- [ ] Создание, сохранение, переименование и удаление профиля работают.
- [ ] Заводской профиль нельзя случайно удалить или перезаписать.
- [ ] Индивидуальные значки томов сохраняются после перезапуска Plasma.
- [ ] Параметры beta3 сохраняются после локального обновления.
- [ ] Сброс к значениям по умолчанию работает.

## Контроль виджета

- [ ] Корневой, загрузочный и системные разделы показываются согласно настройкам.
- [ ] LUKS/LVM, RAID и съёмные USB-накопители группируются корректно.
- [ ] Файловый менеджер открывается нажатием по строке тома.
- [ ] Заполнение, предупреждение и критическое состояние отображаются правильно.
- [ ] Активность чтения/записи обновляется с выбранным интервалом.
- [ ] Фон, текст, скругление и края выглядят правильно.
- [ ] Нет ошибок QML после перезапуска Plasma.

Проверка журнала:

```bash
journalctl --user -b | grep -Ei 'drivecard|qml' | tail -100
```

Перед публикацией журнала удалите домашние пути, имена пользователей, UUID и другие персональные данные.

## GitHub-проверка

Перед слиянием:

- открыть Pull Request из `dev/v0.96-beta4` в `main`;
- дождаться успешной проверки `package`;
- просмотреть diff и убедиться, что нет тега, релиза и случайных сборочных файлов;
- приложить результаты ручной проверки;
- не объединять PR, пока остаются критические ошибки.

## После проверки

Только после подтверждения всех пунктов:

1. Обновить версию в `package/metadata.json` до `0.96.0-beta4`.
2. Добавить раздел beta4 в `CHANGELOG.md`.
3. Обновить `TESTING.md`, `ROADMAP.md` и при необходимости README.
4. Повторно запустить `scripts/check.sh` и `scripts/build.sh`.
5. Проверить содержимое собранного `.plasmoid`, включая авторов и версию.
6. Слить одобренный PR в `main`.
7. Отдельно решить, создавать ли тег и GitHub pre-release.

Создание ветки, PR или тестового пакета само по себе не является выпуском версии.
