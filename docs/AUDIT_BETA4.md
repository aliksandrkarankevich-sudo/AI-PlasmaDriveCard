# Аудит Drive Cards beta4

Проверена ветка `dev/v0.96-beta4`, исходная ревизия `92c8c9f1fcce0120c923fdcedca17d4138356cd9`.
Это статический аудит исходников, исполнение JavaScript-функций с тестовыми данными и проверка сборки, а не замер нагрузки или проверка интерфейса в Plasma.

## Вывод

Полная перепись не обоснована: в коде уже есть раздельные интервалы сканирования и активности, обновление только изменившихся полей списка и отложенное объединение запросов обновления.
При этом найдены конкретные лишние операции, ненадёжная проверка hotplug и пробелы в проверках пакета; небольшие исправления включены в эту ветку.
Исходная реализация доступна в [main.qml до аудита](https://github.com/aliksandrkarankevich-sudo/AI-PlasmaDriveCard/blob/92c8c9f1fcce0120c923fdcedca17d4138356cd9/package/contents/ui/main.qml).

## Внесённые исправления

- **Рудименты:** удалена `_lastScanMs`, которая записывалась, но нигде не читалась. Удалены неиспользуемые свойства `kname`, `kind`, `index` именно у делегата; необходимые роли модели `kname` и `kind` сохранены.
- **Лишние сканирования:** изменения масштаба текста, отступов, толщины полосы и максимальной высоты больше не запускают `findmnt`/`lsblk`. Геометрия остаётся связанной с настройками через QML bindings; включение autoFit непосредственно применяет рассчитанную высоту.
- **Hotplug:** вместо числа непустых строк сравнивается полное содержимое успешного снимка `/proc/partitions` и `/proc/self/mountinfo`. Начальная выборка выполняется сразу; пустой/неуспешный ответ не заменяет базовый снимок.
- **Активность:** `setProperty("active")` вызывается только при смене значения. При переключении показа активности очищаются индикаторы и предыдущая выборка, чтобы не сравнивать счётчики за весь период отключения.
- **Устойчивость настроек:** `_loadProfiles` проверяет, что JSON содержит массив профилей с допустимыми именами. `null` в переопределениях томов больше не ломает формирование сводки; это не полная валидация всех полей пользовательских профилей.
- **Подсказки:** масштаб текста описан относительно базовых шрифтов виджета, а не системного шрифта. Для кривой затухания уточнены направление изменения и нелинейность нулевого значения.
- **Сборка и проверка:** добавлен `build.sh --no-install`, `check.sh` использует его и не меняет установленный виджет. Обычный `build.sh` по-прежнему собирает и устанавливает пакет при наличии `kpackagetool6`.
- **Ложноположительная проверка архива:** исходный `unzip | grep || true` выдавал успех даже при отсутствии `unzip`, что воспроизведено в среде аудита. Теперь Python проверяет читаемость ZIP, CRC и отсутствие резервных копий; сборщик также исключает `.bak`.
- **Инструкции установки:** устранена повторная установка в примере `TESTING.md`, обновлена подсказка перезапуска Plasma в `install.sh`.

Все 32 ключа `main.xml` сохранены, их `cfg_*`-свойства и объявленные значения по умолчанию проверены тестом.
Версия остаётся `0.96.0-beta4`; README не объявляет beta4 опубликованной.

## Что уже сделано рационально

- **Модель списка:** при неизменной структуре `syncModel` не очищает список, а сравнивает поля. Тесты подтверждают отсутствие записей при повторном одинаковом сканировании и обновление только двух полей при изменении свободного места и процента заполнения.
- **Разделение опросов:** тяжёлое обновление информации о томах не выполняется с частотой индикатора активности. При стандартных настройках это один запуск команды сканирования в минуту, около 30 запусков команды активности и 12 запусков команды hotplug; начальные/событийные запросы считаются отдельно.
- **Фон:** `Canvas` запрашивает перерисовку при изменении размера и параметров, а не по постоянному таймеру. Заменять его шейдером без профилирования пока не требуется; это не утверждение о нулевой стоимости отрисовки.
- **Совместимость:** отсутствует необходимость возвращать удалённый C++-плагин только ради нынешней небольшой очистки. Старые упоминания beta3 в документации о выпущенной версии не являются сами по себе рудиментами.

Число запусков команд выведено из таймеров, а не измерено на компьютере пользователя.
Оно не равно точному числу процессов и ничего само по себе не доказывает о проценте загрузки CPU.

## Оставшиеся вопросы

- **AutoFit при неодинаковых строках, приоритет средний:** `measuredRowH` хранит одну высоту последнего измерившегося делегата, а итог умножается на число томов. При индивидуальных размерах значков строки могут различаться; нужна проверка смешанных 50/100/300% и длинного списка, затем расчёт суммарной высоты без зависимости от последнего делегата.
- **LUKS/LVM/RAID, приоритет средний:** группировка зависит от сопоставления имён и одной сохранённой родительской цепочки. Нужны реальные обезличенные `findmnt`/`lsblk` примеры для `/dev/mapper`, многодискового LVM и сложных RAID; текущие тесты не подтверждают все эти топологии.
- **Опрос в фоне, оптимизация после замера:** таймеры не приостанавливаются по видимости. Следует сначала измерить нагрузку с виджетом и без него, а затем определить корректное поведение для скрытой панели/рабочего стола и нескольких экземпляров.
- **Зависание команд, устойчивость:** watchdog есть у основного сканирования, но нет отдельных watchdog для активности и hotplug. Команды читают `/proc`, однако восстановление после отсутствующего ответа не проверено.
- **Неполные/неуспешные сканы, устойчивость:** обработка основного сканирования проверяет наличие и разбираемость вывода, но не полноту JSON-схемы и успех обеих команд отдельно. Стоит добавить соответствующие фикстуры и согласованную обработку ошибок.
- **Выбор точек монтирования:** настройки используют текстовый `findmnt` и декодируют только `\\x20`. Для экзотических имён путей лучше перейти на JSON; это отдельная доработка.
- **Дублирование defaults:** значения представлены в XML, `cfg_*Default` и заводском профиле. Сейчас это не проблема быстродействия, но риск расхождения при развитии; полезен дополнительный тест заводского профиля или единый источник.
- **CI:** существующий workflow Check не включает `dev/**` в push-фильтр. В этом аудите Actions не изменялись; изменение workflow требует отдельного согласования.

## Выполненные проверки

- **Регрессионные тесты:** `node --test scripts/test-logic.cjs`, 16 из 16 успешно на исправленном коде.
- **Контроль исходной версии:** тот же набор на `92c8c9f` даёт 9 успешных и 7 неуспешных тестов. Два падения относятся к новым отсутствующим в исходнике функциям, остальные проверяют прежнее поведение и защиту данных.
- **Пакет:** `bash scripts/check.sh`, 18 успешных проверок, 0 ошибок в среде с Node.js; один из этих 18 пунктов объединяет все 16 JS-тестов.
- **Shell и diff:** все `scripts/*.sh` проверены отдельными вызовами `bash -n`, `git diff --check` без замечаний. Неизвестный аргумент `build.sh` отклоняется с кодом 2.
- **Ограничения:** нет Plasma, `qmllint` и `kpackagetool6`; загрузка QML, графическая сцена, установка и нагрузка на реальном рабочем столе здесь не проверены.

Тесты извлекают фактические JS-функции из QML и запускают их в Node.js с подменённой моделью и конфигурацией.
Они не воспроизводят сигналы, bindings, layout и особенности движка JavaScript Qt; при отсутствии Node.js `check.sh` явно пропускает этот блок, а не требует Node для работы виджета.

## Локальная проверка после обновления

```bash
cd ~/AI-PlasmaDriveCard
git switch dev/v0.96-beta4
git pull --ff-only origin dev/v0.96-beta4
bash scripts/check.sh && bash scripts/build.sh
systemctl --user restart plasma-plasmashell.service
```

Проверь изменение размеров без задержки, выключение/включение активности, применение и повторное открытие настроек, загрузку существующего профиля и подключение USB-накопителя.
Отдельно проверь авто-высоту с неодинаковыми размерами значков; этот известный риск не заявлен исправленным.
